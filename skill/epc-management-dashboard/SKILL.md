# EPC Management Dashboard

Turns project cost, billing and progress data into one decision-ready dashboard plus the
supporting report pack that the **Project Accountant (PA)** and **Project Manager (PM)**
use jointly in the monthly forecast / close cycle.

## Workflow

1. **Gather inputs** — ask for (or locate) the files in `references/data-schema.md`.
   Minimum viable: `project.csv` + `job_cost.csv`. Add `sov.csv`, `trend.csv`,
   `change_orders.csv` for the full pack. Never invent data; if something is missing,
   say which report is skipped and why.
2. **Validate** — run the build script; it reports reconciliation problems
   (SOV total ≠ contract value, actual > committed, negative ETC, progress > 100%).
   Surface every warning to the user; do not silently fix.
3. **Compute** — `node scripts/build_dashboard.mjs --data <dir> --out <dir>`
   writes `dashboard.html` (self-contained, offline) and `metrics.json`.
4. **Interpret** — write the PM/PA narrative using `references/interpretation.md`
   (what each signal means, thresholds, standard actions). Lead with the answer:
   forecast margin, direction vs last month, top 3 drivers, decisions needed.
5. **Deliver** — local files only. Do not publish or upload project financials
   anywhere without the user's explicit approval (client data is confidential).

Run with `--demo` to render the illustrative sample in `assets/sample_data/`
(fictional numbers, clearly labelled as sample in the output).

### Excel export (`--xlsx`)
Add `--xlsx` to either build script to also write a real `.xlsx` with **live formulas**
(blue = input, black = formula; change an ETC and EAC, WIP, EVM and the Summary recalculate).
Project workbook: Summary · Job Cost · By Category · WIP · EVM · SOV · Change Orders · Cash ·
Trend · Alerts (sheets without data are omitted). Portfolio workbook (`portfolio_controls.xlsx`):
Portfolio WIP · Portfolio EVM · Cash · Alerts (+ one project workbook per project folder).
CPI/SPI, SOV front-loading and alert severity carry conditional formatting.
Standalone: `node scripts/export_excel.mjs --metrics metrics.json --out file.xlsx`.
Limits: no embedded charts (use dashboard.html for S-curve); the workbook is generated by a
dependency-free writer — if a user's Excel reports a repair prompt, report it as a bug.
Do not hand-edit numbers in the Job Cost sheet's formula columns; edit the blue inputs.

### Portfolio view (multiple projects)
Put one sub-folder per project (each with the same CSVs) under a portfolio folder, then:
`node scripts/build_portfolio.mjs --data <portfolio-dir> --out <dir>` (or `--demo`)
→ `portfolio.html` + `portfolio_metrics.json` + `projects/<folder>/dashboard.html`
(each portfolio row links to its project dashboard; numbers come from the same engine).
Contents: KPI strip, RAG health + margin bars vs prior month, portfolio WIP schedule
(over/under billing split into liability vs asset — never net across projects),
EVM table with value-weighted CPI/SPI (ΣEV/ΣAC, ΣEV/ΣPV), cash & retainage, cross-project alerts.
Rules: **mixed currencies suppress totals** (convert to one currency and state FX rates);
a project with invalid input is excluded and listed as FAILED in the footer, never silently
counted; mismatched status dates are shown in the header — tell the user.
RAG: Red = any red alert or negative forecast margin; Amber = any amber alert.

## Rules that must hold

- **One source of truth for EAC.** WIP, Job Cost and EVM all use the same forecast
  EAC (`actual + ETC`, PM-signed). The EVM formula-based EACs are *cross-checks*,
  never silently substituted for the PM forecast.
- **Cost-to-cost POC** drives revenue (IFRS 15 / ASC 606 input method) unless the user states
  another measure (units, milestones). Physical progress feeds EVM, not revenue. Say which is used.
- **Loss contracts:** if EAC cost > revised contract value, the full anticipated loss is
  recognized immediately (flag it in red; confirm the policy with the user's auditors).
- **Currency & period:** state currency, status date and prior-period comparison on
  every output. Don't mix periods.
- **Unapproved change orders** are cost exposure, not revenue, until approved/enforceable.
- **Accounting policy is the user's call.** Provide the calculation and flag judgment
  areas (variable consideration, retainage, claims); don't present as audit advice.
- Communicate with the user in their language (Persian if they write Persian);
  keep report labels in English unless asked otherwise.

## Files

- `scripts/build_dashboard.mjs` — validator + calculator + HTML generator (Node ≥18, no deps)
- `scripts/build_portfolio.mjs` — multi-project aggregation view (runs the engine per project folder)
- `scripts/export_excel.mjs` + `scripts/xlsx_writer.mjs` — formula-driven Excel workbooks (no deps)
- `references/formulas.md` — every formula with worked example
- `references/reports.md` — layout and columns of each report
- `references/data-schema.md` — input CSV specification
- `references/interpretation.md` — thresholds, signals, PM/PA actions, meeting agenda
- `assets/sample_data/` — fictional demo project; `assets/sample_portfolio/` — 3 fictional projects
